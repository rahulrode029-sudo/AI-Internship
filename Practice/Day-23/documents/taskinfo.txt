 AI Internship – Day 1 to Day 19

About the Internship

This repository contains my practical work, assignments, experiments, and projects completed during my AI Internship. The internship covers the fundamentals of Python, data analysis, machine learning, NLP, transformers, APIs, SQL, model deployment, LLMs, LangChain, RAG, vector databases, FastAPI, and AI agent development.

The main objective of this internship is to develop practical knowledge by implementing concepts through hands-on projects rather than only studying theoretical concepts.

Throughout the internship, I worked with Python, Machine Learning, Natural Language Processing, Hugging Face Transformers, Flask, FastAPI, SQL, Google Gemini, LangChain, ChromaDB, FAISS, LangGraph, embeddings, semantic search, and Retrieval-Augmented Generation.

# Day 17 – FastAPI RAG API

## Objective

## Technologies

* FastAPI
* LangChain
* Gemini
* ChromaDB
* Embeddings
* Python

## Practical Project

A FastAPI-based RAG application was developed.

The API allows a user to:

1. Provide a document.
2. Process the document.
3. Create embeddings.
4. Store vectors.
5. Ask a question.

The application follows:

**User → FastAPI → Document Processing → Embeddings → ChromaDB → Retriever → Gemini → Answer**

# Day 19 – LangGraph AI Research / RAG Agent

## Objective

Day 19 focuses on building a more structured AI application using LangGraph.

The objective is to combine:

* LangGraph
* RAG
* Retrieval
* Embeddings
* ChromaDB
* Gemini
* Memory
* Agent workflow

into a practical AI application.

## Project

### AI Research / Document Question Answering Agent

The application allows users to ask questions about documents stored inside the `documents` folder.

The system retrieves relevant document information and uses an LLM to generate an answer.

## Architecture

The workflow is:

**User Question**

↓

**LangGraph**

↓

**Retriever**

↓

**Document Search**

↓

**Relevant Documents**

↓

**LLM**

↓

**Generated Answer**

## Main Files

### `app.py`

The main entry point of the application.

It accepts the user's question and invokes the LangGraph workflow.

### `graph.py`

Defines the LangGraph workflow and connects different processing nodes.

### `retriever.py`

Responsible for:

* Loading documents
* Splitting documents
* Creating embeddings
* Creating the vector database
* Retrieving relevant documents

### `llm.py`

Responsible for connecting the application to Google Gemini.

### `memory.py`

Responsible for maintaining conversation-related information.

### `state.py`

Defines the state structure used by the LangGraph workflow.

### `documents/`

Contains the source documents used by the RAG system.

# Environment Setup

The projects are developed using Python and virtual environments.

Example setup:

```bash
python -m venv venv
```

Activate the environment on Windows:

```powershell
venv\Scripts\activate
```

Install the required dependencies:

```bash
pip install -r requirements.txt
```

For projects using Google Gemini, environment variables are stored in a `.env` file.

Example:

```env
GOOGLE_API_KEY=your_google_api_key
```

The `.env` file should not be committed to GitHub.

Add it to `.gitignore`:

```text
.env
venv/
__pycache__/
*.pyc
```
