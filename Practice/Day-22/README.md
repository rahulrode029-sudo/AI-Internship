# Multi-Agent AI Research Assistant

## 1. Project Overview

The Multi-Agent AI Research Assistant is an AI-based research system designed using a multi-agent architecture. Instead of assigning the complete research task to a single AI model, the system divides the task among multiple specialized agents.

The system contains five main agents:

1. Coordinator Agent
2. Research Agent
3. Analyzer Agent
4. Critic Agent
5. Writer Agent

Each agent has a specific responsibility. The agents communicate through a shared state and follow a predefined workflow to transform a user's research question into a structured and validated final answer.

The project demonstrates important concepts of multi-agent AI systems including agent roles, communication, shared state, workflow planning, task delegation, conditional routing, and feedback loops.

## 3. System Architecture

The system consists of five specialized AI agents.

### Coordinator Agent

The Coordinator acts as the manager of the entire workflow.

Responsibilities:

* Receive the user's query.
* Create a research plan.
* Coordinate the other agents.
* Maintain workflow information.
* Manage the overall execution.

### Research Agent

The Research Agent collects and organizes relevant information related to the user's query.

Responsibilities:

* Understand the research question.
* Follow the research plan.
* Collect important information.
* Identify facts, examples, benefits, and limitations.
* Provide research notes to the Analyzer.

### Analyzer Agent

The Analyzer processes the information collected by the Research Agent.

Responsibilities:

* Organize research information.
* Identify important findings.
* Remove irrelevant information.
* Compare information.
* Identify important patterns.
* Prepare structured analysis.

### Critic Agent

The Critic acts as the quality-control agent.

Responsibilities:

* Review the analysis.
* Check relevance.
* Check logical consistency.
* Identify missing information.
* Identify unsupported claims.
* Approve the analysis or request revision.

### Writer Agent

The Writer creates the final answer.

Responsibilities:

* Use the approved analysis.
* Apply critic feedback.
* Organize the final response.
* Produce a clear and understandable answer.

## 4. Workflow

The basic workflow is:

```text
User
  |
  v
Coordinator
  |
  v
Research Agent
  |
  v
Analyzer
  |
  v
Critic
  |
  +--------------------+
  |                    |
Approve              Revise
  |                    |
  v                    v
Writer              Analyzer
  |                    |
  +---------<----------+
  |
  v
Coordinator
  |
  v
User
```

The Critic creates a feedback loop. If the analysis is not satisfactory, the workflow returns to the Analyzer for improvement.

---

## 5. Shared State

The agents communicate through a shared state.

The shared state contains:

```text
user_query
research_plan
research_results
analysis
critic_feedback
revision_count
final_answer
workflow_status
```

The shared state allows information generated by one agent to be accessed by other agents during the workflow.

For example:

```python
state = {
    "user_query": "...",
    "research_plan": [],
    "research_results": "",
    "analysis": "",
    "critic_feedback": "",
    "revision_count": 0,
    "final_answer": "",
    "workflow_status": ""
}
```

## 11. Example Workflow

For the question:

```text
What are the benefits and challenges of artificial intelligence in healthcare?
```

The workflow performs the following operations:

### Step 1

The Coordinator receives the question and creates a research plan.

### Step 2

The Research Agent collects relevant information.

### Step 3

The Analyzer organizes and analyzes the research.

### Step 4

The Critic checks the analysis.

### Step 5

If the analysis requires improvement, the Critic sends feedback to the Analyzer.

### Step 6

The improved analysis is reviewed again.

### Step 7

After approval, the Writer creates the final response.

### Step 8

The final answer is returned to the user.

## 13. Advantages

The multi-agent approach provides several benefits:

* Each agent focuses on a specific task.
* Complex tasks can be divided into smaller tasks.
* Quality checking can be separated from content generation.
* Agents can communicate through shared state.
* The workflow can be extended with additional agents.
* Individual agents can be modified without redesigning the entire system.

---

## 14. Limitations

The current implementation has some limitations:

* The agents use the same underlying language model.
* The Research Agent does not use an external search API.
* Generated information may require external verification.
* The system does not currently store long-term conversation history.
* API usage depends on the availability and limits of the selected model.
